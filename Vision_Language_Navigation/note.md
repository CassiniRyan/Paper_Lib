# Vision-Language Navigation — Paper Notes

This folder cross-lists work in vision-language navigation and closely related language-grounded embodied navigation. The papers span VLN benchmarks, zero-shot ObjectNav, multimodal scene graphs, 3D spatial memory, fast/slow reasoning, world-model feedback, human-aware navigation, and whole-body humanoid VLA navigation. Each note emphasizes visual and language observations, memory representation, reasoning and planning outputs, metric execution boundaries, evaluation protocols, latency, grounding errors, and safety.

## FSR-VLN: Fast and Slow Reasoning for Vision-Language Navigation with Hierarchical Multi-modal Scene Graph

[FSR-VLN](https://arxiv.org/abs/2509.13733) reduces the latency and weak long-range reasoning of VLM-only navigation. It stores an environment as a hierarchical multimodal scene graph spanning rooms, views, and objects. Fast embedding-based retrieval narrows the candidates; expensive VLM reasoning is invoked only when ambiguity remains. This coarse-to-fine “fast then slow” design preserves visual evidence and supports language queries. The paper reports higher retrieval success on humanoid-collected indoor data and substantially less response time than reasoning over tour videos. It is an effective semantic goal selector, but still relies on separate mapping, planning, and control modules and on the quality of the prebuilt graph.

### Hierarchical retrieval and conditional slow reasoning

The Hierarchical Multi-modal Scene Graph stores room-level context, representative viewpoints, and object instances together with images/textual or embedding features and their spatial links. A natural-language instruction is resolved progressively: inexpensive similarity matching first ranks rooms, then views, then objects. Only when fast scores are ambiguous does a vision-language model inspect the narrowed multimodal evidence and refine the selection. The semantic module outputs a goal object/view or goal pose; conventional localization, planning, and humanoid control execute it. It is not an RGB-to-joint VLA policy.

This conditional compute is the main engineering contribution. Long tour videos waste VLM context on irrelevant frames and make response time grow with route length. Structured coarse-to-fine retrieval bounds context, preserves the image evidence needed to distinguish instances, and reserves expensive reasoning for difficult cases. Across four humanoid-collected indoor datasets and 87 varied instructions, the paper reports leading retrieval success and an 82% response-time reduction relative to VLM reasoning over tour video, followed by integration with speech and Unitree G1 navigation.

The evidence mainly validates goal retrieval, not every downstream navigation failure. A prebuilt graph can become stale, and room/view segmentation or embedding mistakes may discard the correct candidate before slow reasoning ever sees it. Thresholds governing fast-versus-slow escalation trade latency against missed goals, yet confidence from modern multimodal models is often poorly calibrated. Online graph maintenance, retrieval recall guarantees, uncertainty-aware escalation, movable-object memory, and end-to-end SPL/collision evaluations would better establish how semantic speedups translate to physical autonomy.

### Fast/slow timing and execution boundary

The fast branch acts on the current view and compact graph context, handling obvious waypoint following, turning, and instruction progress without repeatedly invoking a large reasoner. The slow branch is triggered by ambiguity, long-horizon choice, or failure and queries the hierarchical scene graph for rooms, objects, viewpoints, and relationships. It returns a subgoal or revised route, not motor torque. A geometric controller still verifies free space and executes that subgoal.

This division saves inference only if triggers are calibrated. Too many slow calls erase latency benefits; too few let the fast policy persist with bad grounding. Evaluation should publish calls and latency per episode, trigger precision, graph size, replanning frequency, and recovery after corrupted detections. A probabilistic timestamped graph would prevent stale relations from becoming facts, while a value-of-information test could invoke slow reasoning only when expected improvement exceeds cost. The cleanest comparison would hold perception and low-level control fixed and vary only memory hierarchy and trigger policy.

### Scene-graph schema, reasoning schedule, and benchmark interpretation

The hierarchical graph must preserve metric facts needed for execution as well as semantic facts needed for instruction grounding. Viewpoint nodes connect observations to pose; object nodes carry category, attributes, image evidence, and 3-D location; region or room nodes summarize navigable context; edges encode containment, adjacency, relative direction, and visibility. The fast module can consult a compressed neighborhood around the current node, whereas slow reasoning traverses coarse-to-fine structure and revises a subgoal when the instruction requires unseen context.

Slow-reasoning triggers are a learned or engineered policy in their own right. Ambiguous noun grounding, conflicting observations, loss of progress, or arrival at a decision junction are sensible triggers; fixed periodic calls waste compute. The graph should record which evidence led to a decision so re-perception can target uncertainty rather than merely repeat a view. Results across MP3D, HM3D, and RoboTHOR suggest useful zero-shot transfer, but simulator differences in action granularity, depth, object labels, and navigation mesh complicate aggregate comparisons.

The strongest ablations would equalize perception and LLM model, then remove hierarchy, fast/slow scheduling, re-perception, or individual graph modalities. Report success, SPL, physical distance, collisions, LLM calls/tokens, latency, and recovery after a deliberately wrong node. I would also test instruction compositionality—relations, ordering, and negative constraints—because simple ObjectNav can be solved mostly with room priors. The method becomes most compelling when structured memory resolves language that current-view prompting cannot and does so with fewer expensive reasoning calls.

Repeated runs with identical observations should additionally quantify language-model decision variance and whether that variance materially changes path safety, efficiency, or recovery behavior.

## HA-VLN 2.0: An Open Benchmark and Leaderboard for Human-Aware Navigation in Discrete and Continuous Environments with Dynamic Multi-Human Interactions

[HA-VLN](https://arxiv.org/abs/2503.14229) is primarily a benchmark rather than a controller. It unifies discrete panoramic and continuous-control vision-language navigation while adding dynamic people, personal-space constraints, and socially meaningful language. HAPS 2.0, upgraded simulators, 16,844 human-centric instructions, real-robot validation, and a public leaderboard expose failures hidden by static ObjectNav/VLN tests. The main lesson is that task success alone is insufficient: collision rate and social compliance must also be measured. Benchmark results improve when social context is modeled, but simulation realism and culturally variable notions of appropriate distance remain open issues.

### Task definition, data, and what the benchmark actually tests

HA-VLN 2.0 deliberately spans two action regimes: graph-constrained panoramic choices used by classic VLN and continuous free-space motion closer to a deployed robot. Episodes pair language with environments containing several moving humans, partial observations, personal-space constraints, outdoor/indoor contexts, and motion-language references. HAPS 2.0 expands human trajectories and refines alignment between what people are doing and how instructions describe them. In total, 16,844 human-centric instructions support standardized evaluation, and released simulators, agent code, leaderboard, and real-robot trials make comparisons reproducible.

Because this is a benchmark, there is no single mandated network input/output. Baselines receive visual observations, instruction tokens, pose/history, and—depending on the track—candidate viewpoints or continuous observations; they output the next discrete viewpoint/action or continuous navigation command. Metrics must jointly reflect goal success/path efficiency, collisions, and infringement of human comfort rather than rewarding the shortest geometric route alone. Experiments show that explicitly modeling social context reduces collision and improves navigation relative to agents trained for static VLN.

The contribution is therefore diagnostic: it exposes how an agent that scores well in empty scans can fail when several partially observed people move and language implicitly constrains passing behavior. Real-world crowded-indoor tests add credibility, but simulated motion diversity, visual realism, and fixed personal-space rules cannot capture culture, intent, group formation, or vulnerable users. A next benchmark version should separate prediction, etiquette, and emergency avoidance errors; report near-misses and minimum time-to-collision; include interactive humans who respond to the robot; and evaluate calibrated uncertainty and recovery, not only final success.

### What the benchmark measures—and does not

HA-VLN 2.0 varies whether navigation occurs on a discrete connectivity graph or in continuous control, and introduces multiple moving humans whose paths and interactions change what constitutes a good trajectory. An agent must satisfy the language instruction while avoiding collision, respecting personal space, and adapting when people block an intended path. The benchmark therefore needs task success and path efficiency together with human-aware quantities such as collision count, closest approach, discomfort-zone intrusion, waiting or detour behavior, and performance versus crowd density.

Dynamic humans expose a key distinction between prediction and etiquette. Extrapolating motion may avoid impact but still cut through a group or pass uncomfortably close; a socially conservative agent may freeze and never finish. Models should receive clear observations—RGB/depth or simulator state depending on track—and disclose whether future human trajectories are privileged. Strong evaluation separates perception, forecasting, language grounding, and control. Useful future tracks would include humans reacting to the robot, culturally/task-dependent personal space, uncertain intent, wheel versus leg embodiments, and real-robot validation. Leaderboard scores should not compress safety and efficiency into one number without publishing the Pareto trade-off.

### Dataset protocol, metrics, and social-policy caveats

Discrete and continuous tracks test different capabilities. A graph action can abstract away acceleration, footprint, and low-level collision, while continuous motion exposes control delay and how an agent passes a person. Results should never be compared without stating the track and observation regime. Dynamic multi-human episodes also require fixed or seeded human policies so two agents encounter comparable difficulty. If humans replay open-loop paths, the benchmark measures avoidance around movers; if they react, it measures interaction and can produce policy-dependent scenarios.

Human-aware metrics should be reported individually. Navigation success and SPL reward efficiency; collision and minimum separation capture physical safety; personal-space intrusion approximates discomfort; time spent stopped reveals freezing; path deviation and acceleration reflect disruption to the robot's task. A single weighted score embeds contestable social values. Pareto curves over safety and efficiency are more informative, along with breakdowns by density, crossing angle, group formation, and instruction complexity.

Benchmark leakage is another concern: language and room layouts may repeat, simulated pedestrians may have recognizable motion, and privileged human positions can make perception unrealistically easy. Strong submissions should declare detector, tracker, prediction horizon, map access, and whether human intent is observed. Future versions should include sensor noise, partial occlusion, children/wheelchairs/carts as distinct geometries, people who yield or communicate, and real-robot episodes with consent and conservative speeds. The benchmark's value lies in forcing these assumptions into the open, not in crowning one opaque composite score.

## HoloAgent-0: A Unified Embodied Agent Framework with 3D Spatial Memory

[HoloAgent-0](https://arxiv.org/abs/2606.23565) is a robot-agent framework rather than a single navigation network. An Embodied AgentOS converts language requests into skill graphs, schedules resources, monitors execution, and replans or asks for clarification. Persistent 3-D spatial memory grounds object and place references, while embodiment-specific skills execute navigation, motion, and manipulation. The achievement is a common closed-loop interface across heterogeneous robots and long-horizon tasks. Its strength is modularity and runtime feedback; system performance is consequently bounded by the reliability of every skill, memory update, and high-level language decision, and broad evaluations do not replace component-level safety guarantees.

### AgentOS loop, grounded memory, and skill boundary

The three coupled layers have deliberately different outputs. Embodied AgentOS parses a language request into a directed skill graph, resolves dependencies/resources, starts skills, watches typed runtime feedback, and can replan or ask for clarification after failure. The 3-D spatial-memory layer maintains persistent metric/semantic entities and relations so phrases such as “the object beside the table” refer to world state rather than a transient image. The skill layer wraps embodiment-specific navigation, motion generation, search, and manipulation controllers behind common preconditions, arguments, status, and results.

Accordingly, no single history length, Transformer, or action vector describes HoloAgent-0. Foundation/language models operate at planning and grounding level; the invoked skills may use geometric planning, learned perception, RL locomotion, or robot-specific control. Inputs include the user instruction, memory query results, skill feedback, and live perception. Outputs are skill-graph revisions and API-level calls, eventually translated by each skill into robot motion. Evaluations cover spatial memory, long-horizon search/navigation, cross-robot cooperation, motion generation, and mobile manipulation on hardware.

The highlight is bringing the familiar tool-use agent loop—plan, execute, inspect, revise—into a physical system while keeping continuous safety-critical control outside the LLM. Persistent 3-D grounding also reduces repeated rediscovery and makes cross-robot handoff possible. But a shared interface does not make heterogeneous skills equally reliable, and an incorrect memory identity can poison several later decisions. High-level replanning is too slow for collision safety and must remain subordinate to certified/local controllers. Future work should formalize skill contracts and uncertainty, maintain provenance and temporal validity in memory, verify plans before execution, bound resource conflicts, and publish failure taxonomies showing whether errors arise in language planning, grounding, memory, or physical skills.

### Memory/action loop and model boundary

HoloAgent-0's useful abstraction is a persistent 3-D memory that stores observations in a common spatial frame and exposes them to planning, rather than asking a multimodal model to reconstruct layout from a short image history. New RGB-D or reconstructed geometry updates objects, free space, viewpoints, and semantic attributes; a high-level agent queries this memory with the instruction and chooses a goal or interaction. A conventional navigation stack converts that decision into collision-checked motion. The foundation model reasons over a compact world state, not raw point clouds at servo rate.

This separation supports long-horizon tasks and revisiting, but errors become persistent: pose drift duplicates objects, association merges instances, and stale movable objects remain in memory. The system should attach timestamps, provenance, confidence, and negative observations to every entity and explicitly reconcile contradictions. Evaluation needs memory growth, query latency, loop/revisit consistency, and task degradation under injected pose or detection errors. Active perception should select views that reduce uncertainty, while low-level safety must remain independent of language-model output. The central question is not whether the model can describe a remembered room, but whether memory produces better, cheaper, and more recoverable actions than image-history prompting.

### Spatial-memory schema, planning cadence, and grounding tests

Persistent memory should contain at least camera/keyframe poses, observed free and occupied geometry, object hypotheses with multiple views, navigable connectivity, and task-relevant relations. Retrieval must combine semantic similarity with spatial filters and recency; otherwise a large model sees an unordered database rather than a world. HoloAgent-0's unified framework is most useful when the same memory supports object search, route planning, revisiting, and manipulation-oriented final views. High-level reasoning runs when a subgoal changes, while local mapping and control update much faster.

Long-horizon evaluation should measure more than final success. Memory association accuracy, duplicated/forgotten objects, loop consistency, retrieval latency, storage growth, number of foundation-model calls, and recovery after an object moves expose whether 3-D memory actually works. “No-memory,” image-history, 2-D map, and oracle-memory baselines clarify whether gains come from spatial structure or simply longer context. Tasks requiring returning to an earlier object or reasoning about rooms provide stronger evidence than short direct navigation.

The difficult failure is mutually reinforcing geometry and semantics. Drift can place two copies of an object; the semantic model may interpret them as distinct and plan an unnecessary search. Conversely, confident category similarity can cause an incorrect geometric merge. Factorized uncertainty and provenance let the agent revisit the exact view that would disambiguate the hypotheses. The low-level planner must reject unreachable language-model goals and report why. A mature version would treat memory operations—insert, merge, split, invalidate, verify—as explicit actions with costs, making the system an active mapping agent rather than a passive prompt cache.

## MSGNav: Unleashing the Power of Multi-modal 3D Scene Graph for Zero-Shot Embodied Navigation

[MSGNav](https://arxiv.org/abs/2511.10376) preserves images as relations in a multimodal 3-D scene graph instead of compressing every observation into text. Key-subgraph selection limits VLM context, adaptive vocabulary updates support open-set targets, and closed-loop reasoning revises exploration. A visibility-based viewpoint module tackles the “last mile”: stopping where the target is actually observable and reachable. It is training-free and reports strong GOAT-Bench and HM3D-OVON results. The design is especially useful for auditable semantic memory, though online graph construction, foundation-model latency, and perception errors remain practical constraints.

### Multimodal graph and the last-mile viewpoint problem

M3DSG associates metric object/place nodes with dynamically selected image evidence on relational edges rather than reducing every relation to a generated text sentence. Given a language goal, Key Subgraph Selection extracts only relevant nodes, relations, and images for foundation-model reasoning. Adaptive Vocabulary Update adds categories encountered or requested at runtime instead of committing to the detector's original closed list. Closed-Loop Reasoning compares predicted semantic progress with new observations and can revise the exploration choice. Geometric mapping/planning then turns the selected target into motion.

The final Visibility-based Viewpoint Decision is more consequential than it may sound. Finding the correct object node is not enough: stopping behind it, too close, or across an obstruction can satisfy map distance while failing the task. The module scores candidate final poses for target visibility and physical feasibility, outputting an executable endpoint. Thus network/VLM inputs are a compact multimodal subgraph plus instruction and current state; outputs are semantic exploration targets and a final viewpoint, not low-level joint commands. The method is zero-shot, with evaluation on GOAT-Bench and HM3D-OVON.

Preserving visual evidence postpones irreversible semantic compression and lets a VLM re-inspect ambiguous relationships. Key-subgraph selection also controls context and cost. Yet graph construction still depends on pose, open-vocabulary segmentation, and instance association; retrieval can remove the correct evidence before reasoning, and dynamic images can make graph memory large. The viewpoint score is a geometric/visibility proxy rather than proof that the controller can reach and observe the target. Strong extensions include uncertainty-aware association and retrieval, time-aware movable objects, context/memory scaling studies, and end-to-end real-robot evaluation of final visibility, collision, latency, and recovery.

### Modalities, graph query, and execution

MSGNav binds several kinds of evidence to one 3-D scene graph: object category and visual embedding, metric position/extent, room or region membership, observed images, and relational edges. For a text goal, a language or multimodal model reasons over this compact graph to rank known objects or promising unexplored regions. The selected node becomes a geometric subgoal; mapping, path planning, and obstacle avoidance execute it. This is zero-shot semantic search, not an LLM directly producing wheel or joint actions.

Multimodality helps when any single cue is weak: visual similarity can distinguish instances, room context supplies commonsense priors, and geometry rules out unreachable candidates. But graph construction is itself an estimator. Pose drift duplicates nodes, detector errors assign wrong labels, and an LLM can turn uncertain edges into confident stories. Strong evaluation should ablate each modality while holding navigation fixed and report node association precision, graph update cost, model calls, and failures by perception versus reasoning. Probabilistic nodes, negative evidence, timestamps, and contradiction repair are natural extensions. Final target confirmation should use a fresh local observation rather than trusting a stale graph entry.

### Graph construction, prompt contract, and cost-aware reasoning

The graph-building front end must solve open-vocabulary detection, depth lifting, instance association, room segmentation, and edge creation. Each node should retain category distribution rather than one label, representative image embeddings, 3-D extent, observation count, and last-seen time. Metric edges allow a selected semantic node to become a navigable waypoint; relational edges support prompts such as finding an object near another object. Multimodal reasoning is useful only because these grounded attributes are compact enough for a foundation model to inspect.

Prompt design is part of the algorithm. Supplying the entire graph eventually exceeds context and adds distractors, whereas an overly aggressive summary removes rare but decisive nodes. Retrieval should first select reachable rooms, candidate categories/attributes, and frontier nodes; the model should return a structured node identifier with rationale/confidence, not free-form coordinates. A geometric validator rejects nonexistent or unreachable IDs. Call caching and event-triggered prompting reduce latency and cost.

Evaluation should hold detector, mapper, controller, and LLM fixed while comparing graph modalities and retrieval schemes. Beyond success/SPL, report association quality, prompt size, calls, wall-clock latency, object confirmation precision, and recovery from a planted false node. Scene-graph gains on simulation may partly reflect clean depth and poses; real tests need clutter, repeated instances, moved objects, and viewpoint changes. My preferred extension is Bayesian graph maintenance with negative evidence and active views selected by expected reduction in target uncertainty. This would turn LLM commonsense into one prior among measured evidence rather than the final authority.

## SG-Nav: Online 3D Scene Graph Prompting for LLM-based Zero-shot Object Navigation

SG-Nav constructs an online 3-D scene graph from open-vocabulary detections and spatial relations, then supplies a compact graph prompt to an LLM for zero-shot ObjectNav decisions. Frontier or waypoint planning executes the chosen exploration target, and new observations update the graph. The key idea is replacing long image histories with a structured, spatially grounded prompt that an LLM can reason over efficiently. It improves interpretability and category generalization without task-specific policy training. Dependence on object detection, graph association, and LLM commonsense can still produce hallucinated or overly confident plans.

### Graph construction, hierarchical prompting, and re-perception

Online RGB-D/pose observations produce object instances that are grouped into higher-level regions/rooms and connected by metric and semantic relationships. The graph preserves more context than a list of nearby detections: object–object, object–group, and group–room structure can express where an unseen target is plausibly located. A hierarchical chain-of-thought prompt asks the LLM to traverse this structure from coarse context toward candidate objects/frontiers. Its output is an exploration target; conventional mapping and waypoint control execute motion and then add newly observed nodes.

A re-perception mechanism revisits inconsistent graph evidence so a single detector error need not permanently determine the route. The system is zero-shot—LLM commonsense and open-vocabulary perception replace navigation-policy training—and decisions are inspectable through selected graph nodes and reasoning. Tests on MP3D, HM3D, and RoboTHOR report more than ten percentage points of success-rate improvement over prior zero-shot systems and, on MP3D, performance above compared supervised agents.

The scene graph is a useful prompt compression and persistent spatial memory, but hierarchical reasoning can amplify early structural errors: a wrong room assignment prevents fine-level search from seeing the right object. Re-perception helps only when the robot chooses to observe the disputed region, and chain-of-thought plausibility is not calibrated probability. Graph maintenance, detector/instance association, LLM latency, and repeated calls remain real costs. Future work should use probabilistic graph beliefs, active views selected to resolve ambiguity, explicit prompt-cost budgets, dynamic-object timestamps, and real-robot tests that separate semantic reasoning failures from mapping and controller failures.

### Online graph lifecycle and grounding safeguards

SG-Nav constructs its 3-D scene graph during exploration rather than assuming an oracle map. RGB/depth detections are lifted into object nodes with positions and visual evidence; room or region nodes and spatial/containment edges compress experience. The text goal and graph are serialized into an LLM prompt, which selects a likely object, region, or frontier. A metric planner turns that symbolic choice into a reachable waypoint. The LLM contributes commonsense search priors, not collision avoidance.

The online lifecycle is where most failures occur. Observations must associate with existing nodes despite viewpoint change and pose drift; missing detections are negative evidence only when an object should have been visible; moved objects require stale edges to be revised. Prompt length grows with exploration, so summarization can remove decisive clues. Evaluation should publish graph precision/recall, duplication, prompt tokens and latency, calls per episode, and success after injected map errors. Confidence-weighted nodes, timestamps, reversible merges, and reachability filtering should precede LLM selection. A fresh visual confirmation should be mandatory before declaring success.

### LLM grounding, graph compression, and reproducibility

SG-Nav's prompt must bridge symbols and metric reality. Object nodes need stable IDs, class probabilities, 3-D centroids or boxes, room membership, representative crops, and observation confidence; frontier nodes need position, reachability, and exploration value. The LLM should choose among these IDs or return a room/frontier ranking in structured form. A deterministic parser and metric planner then prevent hallucinated coordinates from reaching the controller. Online updates merge repeat observations and add newly discovered structure after every executed subgoal.

The scene graph is also a compression policy. Including every detection makes prompts long and noisy; retaining only high-confidence objects can delete the target. Experiments should vary graph pruning, hierarchy, prompt format, LLM, and call schedule while holding detector and planner fixed. Report tokens, calls, latency, navigation distance, success/SPL, node association accuracy, and final target-verification precision. Oracle graph and oracle language reasoning baselines separate mapping from commonsense value.

Zero-shot results are credible when goals, categories, layouts, and linguistic forms are not tuned to the evaluation environments. Room priors can be powerful but brittle: a washing machine may sit in a hallway, or a chair may occur everywhere. The agent should combine priors with accumulated negative evidence and revise its plan when a likely room is exhausted. A probabilistic graph and belief update would formalize this process. For real deployment, moved objects, repeated instances, pose drift, and absent targets are essential; the correct outcome for an absent goal is a calibrated failure after efficient coverage, not endless LLM-driven wandering.

These safeguards are essential for reliable unattended operation in practice.

## SysNav: Multi-Level Systematic Cooperation Enables Real-World, Cross-Embodiment Object Navigation

SysNav coordinates semantic target reasoning, building-scale spatial memory, global planning, local obstacle avoidance, and embodiment-specific control rather than asking a VLM to solve everything. Different levels exchange confidence and failure feedback, allowing recovery when semantic guesses or routes fail. The system is evaluated in many real-world trials and on multiple mobile embodiments. Its contribution is systems integration for long-range ObjectNav and cross-robot reuse. Such modularity helps diagnosis, but end-to-end success remains the product of many imperfect components and the cost of mapping or VLM calls can be significant.

### Three levels, structured memory, and cross-embodiment interface

At each step SysNav receives a 360-degree RGB panorama and a 3-D LiDAR point cloud, and ultimately emits continuous linear and angular velocity commands. The high level builds a three-layer scene representation: room nodes store masks, room type, and a representative panorama; viewpoint nodes sparsely store poses, coverage, and best-view images; object nodes store open-vocabulary category, confidence, 3-D points/bounding box, representative crop, and task-requested attributes. Edges encode room connectivity, containment, visibility, and queried object-object relations. VLM calls are used selectively for room labels, task-specific attributes/relations, and deciding which room is most plausible—not for every motor action.

The mid level alternates in-room coverage with cross-room search. Candidate viewpoints are scored by newly visible free/unknown boundaries; sampled candidates are ordered by a traveling-salesperson solve inside a rolling local/global horizon. On discovering a new room, an early-stop VLM query can switch exploration immediately if the target is likely there. Otherwise room histories and graph context guide which connected room to visit next. The mid level emits waypoints. A low-level base-autonomy layer performs waypoint following, collision avoidance, and terrain analysis using embodiment-specific controllers, allowing the same semantic/planning logic to drive a Mecanum base, Unitree Go2, or G1.

This is a strong argument for systematic decomposition. VLMs operate where commonsense is useful and latency is tolerable; geometric coverage handles exhaustive search; conventional control owns rapid safety. Real hardware uses a Livox Mid-360 and Ricoh Theta Z1, with additional onboard LiDAR for legged locomotion. The paper reports 190 real-world episodes across three bodies and 8,195 simulated episodes, with a 4–5x real-world improvement over compared ObjectNav baselines.

The result depends on many interfaces: panoramic detection must align with LiDAR, rooms must be segmented sensibly, graph identity must persist, and low-level feasibility differs sharply by body. A laptop-class RTX 4090 also weakens claims of lightweight deployment. Cross-embodiment reuse is mainly above the controller, not evidence that one motion policy transfers between wheels and legs. Future work should propagate uncertainty through graph and room choices, learn recovery from contradictory observations, benchmark compute/API latency and map growth, and include dynamic people and movable objects in the persistent representation.

### Cooperation signals and cross-embodiment limits

The levels communicate more than a one-way goal. High-level reasoning reprioritizes rooms when new evidence appears; middle-level coverage reports explored viewpoints and unreachable candidates; low-level autonomy reports blocked paths or terrain infeasibility. This feedback prevents a plausible VLM guess from being retried indefinitely. Sparse viewpoint storage and room summaries bound memory, while task-specific VLM queries are reserved for attributes or relations that an open-vocabulary detector cannot resolve cheaply.

Cross-embodiment reuse occurs above robot-specific control; it does not mean Mecanum, Go2, and G1 share actuation or traversability. A doorway reachable by wheels may be unsafe for a humanoid carrying an object, so feasibility must flow upward and alter room/viewpoint costs. Evaluation should separate target discovery, room choice, route feasibility, collision, and final verification per embodiment. A common affordance interface—clearance, slope, step capability, turning radius, payload—would make reuse more principled. Onboard compute and cached language embeddings would test whether the large external GPU is necessary for performance.

### System-level experiment design and reusable abstraction

SysNav's scene representation is unusually concrete: room nodes hold semantic type, panorama and mask; viewpoint nodes store pose, visibility coverage and representative imagery; object nodes store open-vocabulary category, confidence, points or bounding box, attributes and crops. Containment, connectivity, visibility, and queried object relations form edges. This schema allows the VLM to reason at room scale without processing raw sensor history and lets deterministic coverage operate inside a room.

The rolling-horizon viewpoint planner scores newly exposed free/unknown boundaries and uses a traveling-salesperson ordering to reduce redundant motion. Early-stop reasoning after room discovery is valuable because completing geometric coverage of an obviously promising room can waste time. The low level receives waypoints and handles collision and terrain with embodiment-specific autonomy. The reported 190 physical episodes across three bodies and 8,195 simulation episodes are meaningful scale, but confidence intervals and per-environment/per-target breakdowns are needed to interpret the 4–5× improvement.

Strong ablations remove room reasoning, object relations, early stopping, viewpoint ordering, and low-level feedback. Compute should include VLM/API calls, panoramic processing, graph update and the laptop RTX 4090. Cross-embodiment tests should reuse the same high-level decisions in matched buildings while exposing different reachability constraints. The reusable abstraction should be an affordance-aware waypoint request, not a point assumed feasible for all robots. If a G1 cannot cross clutter that a wheeled base can, failure feedback must update the planner instead of repeatedly retrying. This interface is the paper's best systems contribution and should be standardized and measured explicitly.

## TANGO: Humanoid Navigation in Cluttered Environments with a Whole-Body Vision-Language-Action Model

[TANGO](https://arxiv.org/abs/2609.09158) maps a natural-language instruction plus egocentric RGB directly to 29-DoF humanoid action targets, treating arms, torso, and gait as part of navigation. Its simulation data pipeline combines global planning, kinematic whole-body motion generation, obstacle-aware editing, and RL tracking to create feasible supervision. This is novel because it learns language-conditioned whole-body traversal rather than issuing planar waypoints to a fixed locomotion policy. It transfers zero-shot to a Unitree G1 in reported tests. The direct policy may be difficult to verify, and RGB-only partial observability or instructions outside the synthetic distribution remain important risks.

### VLA interface and synthetic whole-body supervision

TANGO receives an egocentric RGB observation plus a natural-language route/traversal instruction and directly predicts 29-DoF joint-space action targets for downstream G1 whole-body control. Arms, torso, and gait are therefore action dimensions rather than fixed posture around a planar base. The vision-language-action model must learn that wording and scene geometry imply coordinated behaviors such as narrowing shoulders, moving an arm past clutter, rotating the torso, or changing gait—not just choosing forward/turn waypoints.

Because large human demonstrations of collision-free humanoid navigation do not exist, supervision is synthesized in four stages. A global planner selects a collision-free route; kinematic whole-body generation produces body motion along it; obstacle-aware editing adjusts links to actual 3-D clearance; and an RL tracker converts those references into dynamically executable trajectories. Rendered egocentric images, instructions, and tracked 29-joint targets then train the VLA entirely in simulation. This pipeline is as important as the model: it transforms geometric paths into action labels that respect the morphology and dynamics.

The highlight is collapsing the traditional gap between semantic navigation and whole-body clearance. Modular baselines can choose the right corridor but still strike it with an elbow; TANGO learns visual-language-conditioned posture continuously and reports strong simulation results plus zero-shot transfer to a physical G1. The same directness makes assurance difficult. Monocular RGB hides metric depth and occluded geometry, and synthetic language/motion correlations may shortcut true grounding. Joint prediction also provides no explicit collision certificate. Recurrent multi-view memory, depth/uncertainty fusion, an independent swept-volume safety filter, intervention/clearance metrics, and tests on compositional instructions and moving obstacles are necessary next steps.

### Action semantics, temporal context, and independent safety

Although described as a whole-body VLA, the model predicts desired 29-joint targets rather than raw torque. A downstream controller and servo loop realize those targets, giving stabilization and limiting authority. The model must infer metric clearance and motion phase from egocentric RGB plus language; with only a short context, an obstacle leaving view or a passage behind the camera becomes unobservable. Training data generated by planning, motion editing, and RL tracking implicitly teaches the action distribution of the specific robot and controller.

The highlight is embodiment-level supervision: language about passing sideways or keeping an arm clear maps to coordinated posture, not a planar symbol. But imitation can exploit synthetic correlations among wording, appearance, and standard trajectories. Tests should paraphrase instructions, alter textures and obstacle shapes, reverse layouts, and measure link clearance, collision impulse, joint saturation, and intervention. Depth or multi-view memory would reduce monocular ambiguity. An independent swept-volume checker should filter proposed joint chunks, while uncertainty can slow the robot when instruction or scene lies outside training support.

### Dataset synthesis, VLA architecture questions, and evidence standards

The synthetic pipeline first creates a collision-free base route, then expands it into articulated kinematic motion whose shoulders, elbows, torso, and legs respect scene geometry. Obstacle-aware editing corrects link clearance, and an RL tracker executes or rejects the reference under dynamics. Only successful tracked trajectories should become paired egocentric images, instruction text, and 29-joint targets. This acceptance step prevents the VLA from imitating geometrically attractive but dynamically impossible poses, although it can also censor difficult behaviors and narrow diversity.

Architectural details are essential for interpretation: visual backbone and image resolution, language encoder, number and duration of frames, whether action targets are single-step or chunks, causal memory, fusion mechanism, action normalization, and control rate. A Transformer with temporal tokens can remember occluded obstacles and infer motion phase; a single-image policy cannot. The downstream joint controller's gains and limits determine how much “control” belongs to the VLA versus stabilization. These should be documented with end-to-end latency.

Evaluation should compare language-conditioned whole-body action with waypoint-plus-tracker, RGB-only ablations, oracle depth/scene geometry, and motion generation without RL feasibility filtering. Measure instruction completion, path efficiency, link-wise clearance, collision, fall, action smoothness, and generalization across paraphrases, obstacle geometry, textures, and layouts. Zero-shot real G1 demonstrations are promising but require repeated trials and interventions. The key risk is shortcut learning from synthetic correlations. Counterfactual scenes where the same instruction demands a different posture, plus an external collision shield, would provide much stronger evidence of genuine language-grounded spatial control.

## VLFM: Vision-Language Frontier Maps for Zero-Shot Semantic Navigation

VLFM performs training-free ObjectNav by attaching vision-language relevance values to an exploration map. A pretrained image-language model scores observations for the requested object, these values are projected into a map, and a frontier policy balances semantic promise with geometric exploration. Conventional mapping and collision avoidance handle execution. The elegant contribution is turning foundation-model similarity into a spatial search heuristic without collecting navigation training data. It generalizes to open-vocabulary goals and has real-robot demonstrations, but inherits VLM biases, can chase visually correlated distractors, and uses a mostly local view of semantic evidence.

### Occupancy frontiers plus language-grounded value map

Depth observations build a metric occupancy map and expose frontiers between explored free space and unknown space. In parallel, RGB views are scored against the text goal by a pretrained vision-language model; directional/local image relevance is projected into a persistent value map. Candidate frontiers inherit semantic promise from nearby values, and a policy selects the next frontier by balancing that promise with geometric exploration. Once the target is detected, ordinary local planning/collision avoidance approaches and stops near it. Thus the foundation model outputs semantic relevance, not wheel or leg commands, and no task-specific navigation policy is trained.

This division is elegant because geometry answers “where can I move?” while Internet-pretrained semantics answers “where is the object likely to be?” Values persist spatially rather than vanishing with the current camera view. VLFM reports leading zero-shot SPL on Gibson, HM3D, and MP3D and demonstrates office ObjectNav on Boston Dynamics Spot without prior environment knowledge.

Similarity is not probability or object verification. A model can favor a kitchen-looking area for “microwave,” chase posters/reflections, or miss an unusual instance; projecting scores through imperfect pose/depth can create durable false hotspots. Frontier selection is also myopic compared with room/topological reasoning and can revisit local maxima. Calibrated open-vocabulary detection, negative evidence and temporal decay, uncertainty-aware map fusion, history/topological memory, and explicit final-view reachability would improve robustness. Reporting VLM inference cost and semantic-versus-geometric failure breakdowns is essential for understanding real deployment gains.

### Score projection and failure attribution

VLFM samples or partitions the camera view, computes text–image similarity for the goal, and projects directional scores through depth and pose into a persistent map. Frontier utility combines geometric factors such as distance or unexplored area with nearby semantic value. The chosen frontier becomes a waypoint executed by an ordinary navigation stack. This clean boundary means semantic scoring can be replaced without retraining locomotion and makes the zero-shot claim precise.

Persistent value is useful but needs negative evidence and age. One mistaken high score can attract repeated visits; failing to see a small object from one angle should not erase a room. Similarity distributions also vary by category. Evaluation should separate target detection, semantic frontier choice, mapping/localization, and control and report inference cost. Calibration, view-quality weighting, temporal decay, room priors, and final detector verification would reduce false arrival. Real-robot tests should include correlated distractors and goals absent from the building.

Frontier scores should also be normalized for travel cost and visibility, so a semantically attractive but occluded or unreachable cell cannot dominate a nearby informative observation indefinitely.

### Component choices, map update, and meaningful zero-shot ablations

VLFM's semantic score generally comes from a pretrained image–text encoder, while an open-vocabulary detector or segmentation model can verify a target. Depth builds obstacle/free-space geometry and allows each image sector's similarity to be projected into world coordinates using the current camera pose. A frontier detector extracts free/unknown boundaries; frontier utility blends semantic value, distance and exploration terms; a classical shortest-path/local controller executes the selected point. No navigation-policy gradient is required, which is the substance of “zero shot.”

Projection choices matter. Scores can be max-, mean-, or confidence-fused over views; negative observations can decay a cell; pose uncertainty can blur evidence spatially; and view frustum/occlusion determines whether absence is informative. Without these rules, persistent maps can become repositories of early mistakes. The final stop condition must distinguish seeing a target from merely entering a semantically plausible area and verify that the object is reachable from the robot's final pose.

Fair ablations hold geometry and control constant while replacing vision-language values with distance-only frontier exploration, room priors, detector confidence, or oracle target direction. Report success, SPL, distance until first target view, false detections, frontier revisits, inference time and map memory per goal category. Separate common Internet-like objects from visually unusual instances and include distractors with strong contextual similarity. The core idea is elegant and reusable, but similarity is a heuristic utility rather than probability. Calibrating it from task-agnostic data or maintaining category-specific score distributions would make frontier ranking substantially more reliable without giving up open vocabulary.

## WMNav: Integrating Vision-Language Models into World Models for Object Goal Navigation

[WMNav](https://arxiv.org/abs/2503.02247) wraps VLM reasoning in a modular world-model loop that predicts decision outcomes and compares them with later observations. An online Curiosity Value Map stores predicted/explored state, and a two-stage proposer first explores broadly then localizes the target precisely. Feedback between imagined and observed states is intended to reduce hallucination and wasteful interaction. Reported HM3D and MP3D results improve success and exploration efficiency over prior zero-shot agents. Prediction is still semantic and approximate rather than a physics simulator, so errors in VLM judgments, mapping, or pose can accumulate.

### Predict–observe feedback and two-stage action proposal

WMNav decomposes a VLM agent into a world-model module, memory, action proposer, and feedback loop. From the goal, mapped observations, and candidate navigation decisions, the world model predicts likely semantic outcomes before physical execution. The online Curiosity Value Map records where the agent expects useful information and what has actually been explored. After motion, the new view is compared with the predicted outcome; disagreement feeds back into memory and the next policy decision, reducing reliance on a single hallucinated VLM answer.

Action proposal changes by search phase. Broad exploration ranks frontiers/regions likely to reveal the category; after credible target evidence appears, precise localization proposes a final approach rather than continuing coarse exploration. Conventional map/planner/controller components execute the selected target, so the VLM/world model emits semantic values and candidate decisions, not motor torques. On HM3D, reported absolute gains are +3.2% success and +3.2% SPL; on MP3D they are +13.5% success and +1.1% SPL over compared zero-shot methods.

The useful novelty is treating prediction error as navigation evidence. Many prompted agents make a choice but never ask whether the world changed as expected; WMNav closes that epistemic loop and makes memory action-dependent. Still, its “world model” is a VLM-based semantic forecast, not learned metric dynamics, and both forecast and observation interpretation may share the same bias. Curiosity values can become self-reinforcing under pose/map errors. Multiple-model uncertainty, independent target verification, counterfactual candidate scoring, longer-horizon/topological memory, and real-robot latency/failure analysis would clarify when imagined feedback genuinely reduces costly interaction.

### Internal state, prediction error, and useful ablations

The Curiosity Value Map should be read as an action-conditioned belief over where useful semantic evidence may appear. Before execution, the world model predicts what a candidate frontier or viewpoint is likely to reveal; after the geometric controller moves, perception records the actual view and updates value according to novelty and prediction mismatch. Broad exploration and target-localization proposal stages use this shared state differently. The output of the learned reasoning layer is a spatial subgoal, while mapping and local control remain responsible for reachability and collision avoidance.

A closed loop does not guarantee independent correction when the same VLM produces both expectation and interpretation. A kitchen-biased model can predict a microwave, interpret an ambiguous rectangle as supporting evidence, and reinforce its own error. Critical ablations should replace predicted outcomes with random or heuristic curiosity, use an independent detector for feedback, remove prediction-error updates, and equalize VLM calls. Useful measurements include calibration of predicted discovery, revisits, distance and calls before target evidence, false localization, and map-error sensitivity. Maintaining multiple semantic hypotheses and selecting views by expected information gain would make the “world model” closer to a belief updater than a confident narrative generator.

### Planning horizon, world-model semantics, and stronger tests

WMNav's “world model” predicts semantic observation outcomes of navigation choices, not future robot physics. This distinction determines its natural horizon: it can compare whether entering a kitchen or opening a new sightline is likely to reveal a target, while collision and dynamics remain with the metric planner. The Curiosity Value Map combines prior promise, visited state, expected novelty, and subsequent prediction error. A two-stage proposer first selects regions/frontiers for discovery and later chooses an approach viewpoint once target evidence crosses a threshold.

The feedback loop should store both confirmation and falsification. If a predicted object is absent from a high-visibility viewpoint, its local belief should decrease; if visibility was poor, uncertainty should remain. Pose error and detector miss probability must therefore enter the update. Multiple imagined candidates should be scored before physical movement, with compute cost included. Otherwise a method may improve SPL only by making more expensive model calls.

The reported HM3D and MP3D gains differ substantially, so dataset-specific scene priors and baseline saturation deserve analysis. Results should break down target frequency, room ambiguity, episode length, absent or occluded objects, and map quality. Compare semantic prediction with learned co-occurrence, LLM room priors, frontier-only exploration, and an oracle, all using the same controller. For real robots, report VLM latency, network dependence, energy/time per decision, and recovery after a wrong prediction. My assessment is that prediction–observation comparison is a real conceptual advance, but independent perception and calibrated belief updates are required before it deserves the stronger connotation of a dependable world model.
